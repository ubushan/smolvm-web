# Задачи вместо машин: целевая модель и план перехода

## Решения

1. Основной сценарий — **задача**: одноразовая песочница, агент работает автономно, результат — git-ветка на проверку.
2. Постоянная сессия (работа вместе) — та же задача с флагом «не закрывать»: без срока жизни, есть «Сбросить к чистому» с сохранением ветки.
3. Результат — **только через git**. Хост-репозиторий не меняется без явного действия человека.
4. Пользователь — безопасник. Журнал, сеть и решения остаются на виду, но привязаны к задаче; глобальный аудит — отдельный пункт меню, инфраструктура — в ⚙.

## Понятия

| Понятие | Что это | Было |
|---|---|---|
| **Задача** | Песочница + текст задачи + проект + агент + уровень доверия. Состояния: открывается → работает → ждёт вас → готово к проверке → принято / отброшено | сессия песочницы |
| **Проект** | Git-репозиторий на хосте + агент по умолчанию + уровень доверия + скрипт подготовки (`init`) | папка агента, шаблон |
| **Уровень доверия** | Пресет: «Офлайн», «Только нужное» (пакеты + вендор + спрашивать о незнакомых), «Открытый». Внутри — белые списки, секреты, лимиты, срок жизни | trust careful/normal/trusted + отдельные страницы |
| **Агент** | Программа (Claude Code, Codex…) + профиль (память, skills, MCP) | «Агенты» |
| **Входящие** | Всё, что ждёт решения человека, от всех задач | «Решения» |
| Шаблон / чекпоинт | Кэш для быстрого старта, собирается из проекта сам. Пользователь не управляет им | «Шаблоны» |
| Машина | Сырая VM. Только в ⚙ → «Машины» для отладки | «Машины» (главная) |

## Навигация

```
[ Задачи ]  [ Входящие (3) ]  [ Проекты ]  [ Журнал ]             ⚙
```

- **Задачи** (главная): активные сверху, ниже история. «Новая задача»: проект, агент, доверие, текст, «не закрывать».
- **Экран задачи**: вкладки «Агент» (программы), «Что делал» (сеть + команды одной лентой), «Изменения» (diff ветки), «Решения». Кнопки: «Готово», «Принять», «Отбросить», «Изолировать», «+2 ч».
- **Журнал**: текущий «Аудит» + журнал сети, фильтр по задаче.
- **⚙**: Агенты и профили, Секреты, Белые списки, Разрешённые папки, Машины, Виртуализация, Прокси, Сертификаты, Репозитории, SIEM.

## Git-транспорт

У агента нет доступа к удалённому репозиторию и учётных данных git. Всё идёт через bundle:

1. **Открытие.** На хосте `git bundle create in.bundle <base>` (текущий HEAD или выбранная ветка) → загрузка в VM → `git clone in.bundle /work/<project>` → ветка `agent/<task-id>`. Запоминаем `base` (sha).
2. **«Готово»** (агент сообщил или нажал человек). В VM: коммит незакоммиченного («wip: …»), `git bundle create out.bundle <base>..agent/<task-id>` → скачивание.
3. **На хосте** `git fetch out.bundle agent/<task-id>:refs/heads/smolvm/<task-id>`. Только fetch: на хосте не выполняются ни хуки, ни checkout, рабочая папка не меняется.
4. **Проверка**: `git diff <base>...smolvm/<task-id>` в UI. До решения VM живёт: можно попросить агента доделать, тогда шаг 2 повторяется.
5. **«Принять»** оставляет ветку `smolvm/<task-id>`; вливает её человек сам или кнопкой (только fast-forward или merge без конфликтов). **«Отбросить»** удаляет ветку и VM.

Проверки при ревью (на них ориентирован безопасник): изменения в `.github/workflows`, `.gitlab-ci.yml`, git-хуках, `package.json` scripts, lock-файлах, новые зависимости, бинарные файлы, подозрительные строки (тот же детектор, что в ревью профиля). Коммиты агента не должны менять `.git/config` хоста: bundle переносит только объекты и ref.

Папка без git: прежний механизм рабочей копии ([lib/review.js](../lib/review.js)) остаётся как запасной путь, с предложением сделать `git init`.

## Этапы

Каждый этап оставляет приложение рабочим.

1. ✅ **Git-транспорт на сервере.** Новый `lib/gitwork.js`: bundle на вход, bundle на выход, fetch, diff, принять / отбросить. В `sandbox.open()` для git-папок — bundle вместо `review.add`. Маршруты `/ui/tasks/:id/finish|changes|diff|accept|discard`. Проверка: задача на тестовом репозитории, ветка появилась на хосте, рабочая папка не тронута.
2. ✅ **Модель задачи.** Запись `sandboxes[name]` → задача со статусом, `base`, `branch`, `persistent`; закрытые задачи остаются в истории. `persistent` отключает TTL и закрытие при простое; «Сбросить» = новая VM из шаблона + bundle с веткой задачи.
3. ✅ **Экраны «Задачи», «Новая задача», экран задачи.** Переиспользуются `session.js` (вкладки сеанса), `agentwizard.js` (шаги выбора), `review.js` (diff). «Входящие» — из `decisions.js`.
4. ✅ **Проекты.** Репозиторий + агент + доверие + `init`. Шаблон-чекпоинт на проект собирается автоматически (`prepareImage` / `createTemplate`) и обновляется по кнопке в проекте.
5. ✅ **Перенос в ⚙.** Машины, Сеть (белые списки), Директории, Секреты, Профили агентов. Сетевые и папочные настройки конкретной задачи — на её экране.
6. **Уборка.** Удалить дублирующие входы («Агенты» как главная, «Песочница», «Папки машин»), обновить documentation.md и README.
